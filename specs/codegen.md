# codegen.md — актуальная генерация кода языка **Astra**

## 1. Назначение

Документ описывает текущий backend компилятора Astra.
Важное уточнение: текущая реализация **не использует отдельную IR-фазу** и не заявляет constant folding как работающую стадию компиляции.
Генерация кода выполняется напрямую по AST после семантического анализа.

Текущий pipeline:

```text
source .astra
  -> Lexer
  -> Parser
  -> AST
  -> Semantic Analyzer
  -> x86-64 NASM Codegen
  -> nasm + cc + runtime.c
  -> executable
```

---

## 2. Целевая платформа

Backend генерирует x86-64 assembly в синтаксисе NASM.
Сборка выполняется внешними инструментами:

```bash
nasm -felf64 program.asm -o program.o
cc -no-pie program.o runtime.c -o program
```

Используется соглашение вызовов **System V AMD64 ABI**.

---

## 3. Общая архитектура backend-а

Codegen получает AST, уже проверенное семантическим анализатором.
Семантика заранее аннотирует выражения их типами и разрешает перегруженные вызовы.

Основные обязанности codegen:

- собрать layout структур;
- учесть alias-типы;
- сгенерировать метки функций;
- построить стековый кадр функции;
- разместить параметры и локальные переменные;
- сгенерировать выражения и инструкции;
- вызвать runtime-функции для `print`, `input`, `len`, `panic`, `exit`, `assert`, строк и runtime-ошибок;
- сгенерировать проверки деления на ноль и выхода за границы массива.

---

## 4. Runtime

Сгенерированный NASM вызывает функции из `runtime.c`.

Используемые runtime-функции:

```text
astra_print_i32
astra_print_i64
astra_print_u32
astra_print_u64
astra_print_f32
astra_print_f64
astra_print_bool
astra_print_char
astra_print_string

astra_input_string
astra_exit
astra_panic
astra_assert

astra_string_concat
astra_string_eq
astra_string_ne
astra_string_len

astra_rt_div_zero
astra_rt_oob
```

Runtime отвечает за:

- печать значений;
- ввод строки;
- работу со строками;
- аварийное завершение;
- assertion failure;
- runtime-ошибки деления на ноль и выхода за границы массива.

---

## 5. Представление типов в backend

### 5.1. Скалярные типы

| Тип | Представление |
|---|---:|
| `bool` | 1 байт, значение `0` или `1` |
| `char` | 1 байт |
| `int8`, `uint8` | 1 байт |
| `int16`, `uint16` | 2 байта |
| `int32`, `uint32`, `float32` | 4 байта |
| `int64`, `uint64`, `float64` | 8 байт |
| `string` | 8-байтный указатель на C-строку/runtime-строку |
| `unit` | не хранится |

### 5.2. Массивы

Массив `[T; N]` хранится inline как непрерывный блок из `N` элементов.

```text
size([T; N]) = size(T) * N
```

### 5.3. Структуры

Структуры хранятся inline.
Поля размещаются в порядке объявления.
Для каждого поля используется естественное выравнивание по размеру типа, но не более 8 байт.
Размер структуры округляется вверх до максимального выравнивания её полей.

### 5.4. Alias

`type alias` не влияет на layout.
Codegen раскрывает alias к базовому типу.

---

## 6. Имена функций и перегрузка

Семантический анализатор разрешает перегруженный вызов и записывает в AST фактическое имя функции для codegen.

Для пользовательских функций применяется mangling по имени и типам параметров.
`main` сохраняет имя `main`.

Методы структур объявляются как функции вида:

```astra
fn Point.sum(self: Point) -> int32 { ... }
```

Семантика преобразует вызов:

```astra
p.sum()
```

в обычный вызов функции метода с `p` как первым аргументом.
Codegen после этого работает с ним как с обычным вызовом функции.

---

## 7. Стековый кадр функции

Каждая функция генерируется с классическим прологом:

```asm
push rbp
mov rbp, rsp
sub rsp, <frame_size>
```

и эпилогом:

```asm
mov rsp, rbp
pop rbp
ret
```

Локальные переменные размещаются по отрицательным смещениям от `rbp`.

Пример:

```text
x -> [rbp - 4]
y -> [rbp - 8]
```

Frame size вычисляется заранее проходом по AST функции.

---

## 8. Передача аргументов

Используется System V AMD64 ABI.

Целочисленные, булевы, символьные, строковые и адресные аргументы передаются через:

```text
RDI, RSI, RDX, RCX, R8, R9
```

Вещественные аргументы передаются через:

```text
XMM0..XMM7
```

Текущая реализация ограничена:

- не более 6 integer/string/aggregate-параметров в регистрах;
- не более 8 float-параметров в XMM-регистрах.

Агрегаты при передаче копируются во временный буфер/локальную память и передаются адресом.

---

## 9. Генерация литералов

### 9.1. Целые литералы

Генерируются как `mov rax, <literal>` с последующей нормализацией под нужный тип.

### 9.2. Вещественные литералы

Вещественные константы размещаются в секции данных, затем загружаются в `xmm0`:

```asm
movss xmm0, [rel label] ; float32
movsd xmm0, [rel label] ; float64
```

### 9.3. Bool

`true` -> `1`, `false` -> `0`.

### 9.4. Char

`char` загружается как unsigned byte-значение в `rax`.

### 9.5. String

Строковый литерал размещается в `.rodata` как null-terminated C-строка.
Выражение строки возвращает адрес литерала в `rax`.

---

## 10. Переменные и присваивания

### 10.1. Let / Var

Для локальной переменной выделяется место в стековом кадре.
Инициализатор вычисляется и записывается по адресу переменной.

### 10.2. Присваивание

Для скаляра:

1. вычисляется rhs;
2. вычисляется адрес lvalue;
3. значение записывается по адресу.

Для массивов и структур используется побайтовое копирование.

---

## 11. Арифметика и сравнения

### 11.1. Целочисленная арифметика

Используются инструкции:

```asm
add
sub
imul
idiv / div
```

Перед `/` и `%` вставляется проверка делителя на ноль.

### 11.2. Деление на ноль

Схема:

```asm
cmp rbx, 0
jne .ok
mov rdi, <line>
call astra_rt_div_zero
.ok:
```

### 11.3. Сравнения

Сравнения генерируются через `cmp` + `setcc`.
Результат нормализуется в `0` или `1`.

Для беззнаковых типов используются unsigned-условия (`setb`, `setbe`, `seta`, `setae`).
Для знаковых — signed-условия (`setl`, `setle`, `setg`, `setge`).

### 11.4. Float-операции

Для `float32` используются SSE-инструкции `addss`, `subss`, `mulss`, `divss` и сравнения через `ucomiss`.
Для `float64` используются `addsd`, `subsd`, `mulsd`, `divsd` и `ucomisd`.

---

## 12. Битовые операции

Поддерживаются:

```text
~
& | ^
<< >>
```

Генерация:

- `~` -> `not`;
- `&` -> `and`;
- `|` -> `or`;
- `^` -> `xor`;
- `<<` -> `shl`;
- `>>` -> `shr` для unsigned, `sar` для signed.

Количество сдвига маскируется:

```asm
and cl, bits - 1
```

где `bits` — ширина левого операнда.

---

## 13. Логические операции

`&&` и `||` генерируются через ветвления с коротким замыканием.

Для `a && b` выражение `b` не вычисляется, если `a == false`.
Для `a || b` выражение `b` не вычисляется, если `a == true`.

---

## 14. If / While / Break / Continue

### 14.1. If-инструкция

Генерируются метки:

```text
else_<N>
endif_<N>
```

Условие сравнивается с нулём.

### 14.2. If-выражение

`if (cond) { a } else { b }` генерируется как ветвление, где результат выбранной ветки сохраняется во временном месте на стеке, а затем возвращается в `rax` или `xmm0`.

### 14.3. While

Генерируются метки:

```text
while_cond_<N>
while_end_<N>
```

`continue` прыгает на `while_cond`, `break` — на `while_end`.

---

## 15. Массивы

### 15.1. Литерал массива

Литерал массива инициализирует inline-блок памяти поэлементно.

### 15.2. Индексирование

Адрес элемента:

```text
base + index * element_size
```

Перед обращением генерируется runtime-проверка:

```text
0 <= index < N
```

При ошибке вызывается:

```text
astra_rt_oob(line)
```

---

## 16. Структуры

### 16.1. Layout

До генерации функций codegen собирает layout структур:

- имя поля;
- тип поля;
- размер;
- выравнивание;
- offset.

### 16.2. Литерал структуры

Литерал структуры записывает значения полей по их offset.

### 16.3. Доступ к полю

Адрес поля:

```text
base_address + field_offset
```

Если поле скалярное, значение загружается из памяти.
Если поле агрегатное, используется адрес.

---

## 17. Строки

Строки реализованы через runtime и C-строки.

Поддержка:

- литералы в `.rodata`;
- `a + b` -> `astra_string_concat(a, b)`;
- `a == b` -> `astra_string_eq(a, b)`;
- `a != b` -> `astra_string_eq(a, b)` и инверсия результата;
- `len(s)` -> `astra_string_len(s)`;
- `print(s)` -> `astra_print_string(s)`.

---

## 18. Встроенные функции

### 18.1. Print

Выбор runtime-функции выполняется по статическому типу аргумента:

| Тип | Runtime-функция |
|---|---|
| `int32`, малые signed int | `astra_print_i32` |
| `int64` | `astra_print_i64` |
| `uint32`, малые unsigned int | `astra_print_u32` |
| `uint64` | `astra_print_u64` |
| `float32` | `astra_print_f32` |
| `float64` | `astra_print_f64` |
| `bool` | `astra_print_bool` |
| `char` | `astra_print_char` |
| `string` | `astra_print_string` |

### 18.2. Input

`input()` генерирует вызов `astra_input_string`.

### 18.3. Len

- для массива `[T; N]` codegen генерирует константу `N`;
- для строки вызывает `astra_string_len`.

### 18.4. Assert

`assert(cond)` генерирует вычисление `cond` и вызов:

```text
astra_assert(cond, line)
```

### 18.5. Exit / Panic

- `exit(code)` -> `astra_exit(code)`;
- `panic(message)` -> `astra_panic(message)`.

---

## 19. Метафункции

### 19.1. Sizeof

`sizeof(T)` генерирует константу размера типа в байтах:

```asm
mov rax, <type_size>
```

Тип результата — `int32`.

### 19.2. Typeid / Typeof

`typeid(expr)` и `typeof(expr)` возвращают строковый литерал с именем статического типа выражения.

Codegen размещает эту строку в `.rodata` и возвращает адрес:

```asm
lea rax, [rel <type_name_string>]
```

---

## 20. Cast

Явные и вставленные семантикой неявные приведения представлены в AST как `CastExpr`.

Codegen поддерживает:

- integer -> integer с нормализацией размера;
- integer <-> float через SSE-инструкции преобразования;
- float32 <-> float64;
- bool/char <-> числовые преобразования через integer-путь.

---

## 21. Конвейерный оператор

Отдельной генерации для `|>` нет.
Parser превращает `|>` в обычный вызов функции.
Codegen видит уже обычный `CallExpr`.

---

## 22. CLI-режимы, связанные с codegen

Поддерживаются:

```bash
--dump-tokens
--dump-ast
--emit-asm
-o <output_file>
```

`--emit-asm` останавливает компиляцию после генерации `.asm` и не вызывает `nasm`/`cc`.

---

## 23. Ограничения текущего backend-а

1. Нет отдельного IR между AST и NASM.
2. Нет реализованного optimizer/constant folding pipeline.
3. Нет register allocation как отдельного алгоритма; стратегия наивная, через фиксированные временные регистры и стек.
4. Не поддерживаются составные присваивания `+=`, `-=`, `&=` и т.п.
5. Полноценная раздельная многофайловая компиляция не реализована.
6. Строки реализованы через runtime/C-строки, без собственного GC/RC.
7. Печать массивов и структур через `print` не заявляется как поддерживаемая.
