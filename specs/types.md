# types.md — актуальная система типов языка **Astra**

## 1. Назначение

Документ описывает систему типов текущей реализации **Astra**: категории типов,
совместимость, вывод типов, явные и ограниченные неявные преобразования.

Astra является статически типизированным языком: типы выражений определяются на этапе компиляции.

---

## 2. Категории типов

В текущей реализации существуют:

1. `unit`;
2. `bool`;
3. `char`;
4. `string`;
5. знаковые целые типы;
6. беззнаковые целые типы;
7. вещественные типы;
8. массивы фиксированного размера;
9. структуры;
10. синонимы типов `type alias`.

---

## 3. Встроенные типы

### 3.1. Целые типы

| Тип | Размер | Категория |
|---|---:|---|
| `int8` | 1 байт | знаковый |
| `int16` | 2 байта | знаковый |
| `int32` | 4 байта | знаковый |
| `int64` | 8 байт | знаковый |
| `uint8` | 1 байт | беззнаковый |
| `uint16` | 2 байта | беззнаковый |
| `uint32` | 4 байта | беззнаковый |
| `uint64` | 8 байт | беззнаковый |

Целый литерал без ожидаемого типа имеет тип `int32`.
Если есть ожидаемый целочисленный тип, литерал типизируется этим типом.

Пример:

```astra
let a = 10;          // int32
var b: int64 = 10;   // 10 типизируется как int64 по контексту
```

### 3.2. Вещественные типы

| Тип | Размер |
|---|---:|
| `float32` | 4 байта |
| `float64` | 8 байт |

Вещественный литерал без ожидаемого типа имеет тип `float64`.
Если есть ожидаемый вещественный тип, литерал типизируется этим типом.

Пример:

```astra
let x = 1.5;          // float64
var y: float32 = 1.5; // float32 по контексту
```

### 3.3. Bool

```astra
true
false
```

Тип: `bool`.

### 3.4. Char

`char` — однобайтовый символьный тип.

Примеры литералов:

```astra
'A'
'\n'
'\t'
'\\'
'\''
'\0'
```

Поддерживаются:

- сравнение `==`, `!=` между `char`;
- печать через `print`;
- явное приведение между `char` и числовыми типами.

### 3.5. String

`string` в текущем backend представлен как указатель на C-строку/runtime-строку.
Строковый литерал имеет тип `string`.

Поддерживаются:

- конкатенация `+`;
- сравнение `==`, `!=`;
- `len(s)`;
- `print(s)`.

`len(string)` возвращает количество байтов до `\0`, то есть длину в терминах `strlen`, а не количество Unicode code points.

### 3.6. Unit

`unit` — отсутствие полезного значения.
Используется для функций без результата и встроенных функций с побочным эффектом:

```astra
print(10); // unit
assert(true); // unit
```

## 4. Составные типы

### 4.1. Массивы фиксированного размера

Тип массива:

```astra
[T; N]
```

где `T` — тип элемента, `N` — целочисленная константа размера.
Размер является частью типа.

Примеры:

```astra
[int32; 3]
[char; 8]
[[int32; 3]; 3]
```

Совместимы только массивы с одинаковым типом элемента и одинаковым размером.

```astra
[int32; 3] != [int32; 4]
[int32; 3] != [int64; 3]
```

`len([T; N])` возвращает `N`.

### 4.2. Структуры

Структура создаёт новый номинальный тип.

```astra
struct Point {
    x: int32;
    y: int32;
}
```

Тип структуры определяется её именем с учётом `namespace`/`module`.
Две структуры с одинаковыми полями, но разными именами, являются разными типами.

### 4.3. Type alias

```astra
type Count = int32;
```

Alias не создаёт новый тип. `Count` совместим с `int32`.

---

## 5. Номинальная типизация

Для структур используется номинальная типизация.
Совместимость структур требует совпадения имени типа.

Пример:

```astra
struct A { x: int32; }
struct B { x: int32; }
```

`A` и `B` несовместимы, несмотря на одинаковые поля.

Для `type alias` применяется раскрытие alias к базовому типу.

---

## 6. Вывод типов

### 6.1. Вывод типа `let`

`let` может не указывать тип:

```astra
let a = 10;             // int32
let b = 1.5;            // float64
let c = true;           // bool
let d = 'A';            // char
let s = "hello";        // string
let xs = [1, 2, 3];     // [int32; 3]
let p = Point { x: 1, y: 2 }; // Point
```

Вывод локальный: тип переменной равен статическому типу инициализатора.

### 6.2. Вывод типа результата функции

Если функция объявлена без `-> Type`, тип результата выводится по `return`:

```astra
fn add(a: int32, b: int32) {
    return a + b; // функция имеет тип результата int32
}
```

Если функция без явного типа результата не возвращает значение через `return expr`, её результат считается `unit`.

Если в такой функции несколько `return expr`, их типы должны быть совместимы по правилам присваивания.

---

## 7. Совместимость типов

### 7.1. Точная совместимость

Типы совместимы, если они одинаковы после раскрытия alias.

### 7.2. Ограниченные неявные преобразования текущей реализации

Базовая идея языка остаётся строгой: произвольных неявных преобразований нет.
Но текущая реализация поддерживает ограниченные неявные преобразования в контекстах:

- присваивание/инициализация;
- `return`;
- аргументы функции;
- значения по умолчанию;
- согласование веток `if`-выражения;
- выбор перегрузки функции.

Поддерживаемые неявные преобразования:

1. значение типа `int32` может быть принято в контексте любого целочисленного типа;
2. значение типа `float64` может быть принято в контексте любого вещественного типа;
3. точное совпадение типов имеет лучший приоритет, чем неявное преобразование.

Эти правила используются, например, для вызова перегруженных функций:

```astra
fn f(x: int32) -> int32 { return 1; }
fn f(x: int64) -> int32 { return 2; }

let a = f(10); // выбирается f(int32), точное совпадение
```

Если несколько перегрузок подходят с одинаковым score, вызов считается неоднозначным.

### 7.3. Нет неявных преобразований в произвольных бинарных операциях

Бинарные арифметические и битовые операции требуют совместимых типов операндов.
Например, если контекст не заставил литерал принять нужный тип, разные типы могут дать ошибку.

---

## 8. Явные приведения `as`

```astra
expr as T
```

Разрешены явные приведения:

- между числовыми типами;
- между `bool` и числовыми типами;
- между `char` и числовыми типами;
- тождественные приведения.

Примеры:

```astra
let a = 10 as int64;
let b = 1.5 as int32;
let c = 'A' as int32;
let d = 0 as bool;
```

Запрещены приведения:

- `string` к числам и обратно;
- между разными структурами;
- между разными массивами;
- из/в `unit`, кроме тождественного случая.

## 9. Типизация операций

### 9.1. Унарные операции

| Оператор | Операнд | Результат |
|---|---|---|
| `-x` | числовой тип | тип операнда |
| `!x` | `bool` | `bool` |
| `~x` | целочисленный тип | тип операнда |

### 9.2. Арифметика

| Оператор | Типы | Результат |
|---|---|---|
| `+` | числовые одинакового типа | тот же тип |
| `-` | числовые одинакового типа | тот же тип |
| `*` | числовые одинакового типа | тот же тип |
| `/` | числовые одинакового типа | тот же тип |
| `%` | числовые одинакового типа | тот же тип |

Для `string` оператор `+` означает конкатенацию строк.

### 9.3. Логические операции

| Оператор | Операнды | Результат |
|---|---|---|
| `&&` | `bool`, `bool` | `bool` |
| `||` | `bool`, `bool` | `bool` |

### 9.4. Битовые операции

| Оператор | Операнды | Результат |
|---|---|---|
| `&` | целые одинакового типа | левый тип |
| `|` | целые одинакового типа | левый тип |
| `^` | целые одинакового типа | левый тип |
| `<<` | целое, целое | левый тип |
| `>>` | целое, целое | левый тип |

Для `<<` и `>>` правый операнд должен быть целочисленным, но не обязан иметь тот же тип.
Количество сдвига в codegen маскируется по ширине левого операнда.

### 9.5. Сравнения

`==` и `!=` поддерживаются для:

- числовых типов при совпадении типов;
- `bool`;
- `char`;
- `string`;
- одинаковых массивов;
- одинаковых структур.

`<`, `<=`, `>`, `>=` поддерживаются для числовых типов.
Результат любого сравнения — `bool`.

### 9.6. Индексирование

Если `arr: [T; N]`, то `arr[i]` имеет тип `T`, если `i` — целочисленный тип.

### 9.7. Доступ к полю

Если `s: S`, а `S` имеет поле `f: T`, то `s.f` имеет тип `T`.

### 9.8. If-выражение

```astra
if (cond) { a } else { b }
```

- `cond` должен быть `bool`;
- ветки должны иметь одинаковый тип либо быть согласуемыми через ограниченное неявное преобразование;
- результат имеет тип согласованных веток.

### 9.9. Метафункции

| Выражение | Тип результата | Значение |
|---|---|---|
| `sizeof(T)` | `int32` | размер типа в байтах по текущему layout codegen |
| `typeid(expr)` | `string` | строковое имя статического типа выражения |
| `typeof(expr)` | `string` | строковое имя статического типа выражения |

---

## 10. Встроенные функции

```text
print(value) -> unit
input() -> string
len(value) -> int32
exit(code: int32) -> unit
panic(message: string) -> unit
assert(condition: bool) -> unit
```

`print` принимает:

- целые типы;
- вещественные типы;
- `bool`;
- `char`;
- `string`.

`len` принимает:

- `string`;
- массив `[T; N]`.

---

## 11. Ограничения текущей реализации

1. Нет nullable-типов.
2. Нет динамических массивов.
3. Нет generic-типов.
4. Нет пользовательской перегрузки операторов.
5. Нет функций как значений и лямбд.
6. Нет полноценного анализа всех путей возврата как отдельной CFG-фазы.
7. Не реализованы составные присваивания `+=`, `-=`, `&=` и т.п.
