# semantics.md — актуальная семантика языка **Astra**

## 1. Назначение

Документ описывает смысл конструкций языка Astra в текущей реализации компилятора:
разрешение имён, области видимости, типизацию, вызовы функций, перегрузку, методы,
модули и runtime-проверки.

---

## 2. Общая модель

Astra — статически типизированный компилируемый язык с value semantics.

Основные свойства текущей реализации:

- каждое выражение получает статический тип на этапе семантического анализа;
- локальные переменные имеют блочную область видимости;
- `let` создаёт неизменяемую переменную;
- `var` создаёт изменяемую переменную;
- массивы и структуры передаются и присваиваются как значения;
- функции вызываются по значению;
- есть перегрузка функций по типам параметров;
- есть ограниченные неявные преобразования для контекстов вызова/присваивания;
- codegen генерирует x86-64 NASM напрямую по AST после семантики.

---

## 3. Области видимости и разрешение имён

### 3.1. Области видимости

Новые области видимости создают:

- модульная директива `module`;
- `namespace`;
- функция;
- блок `{ ... }`;
- параметры функции.

### 3.2. Модульная область

Если файл начинается с:

```astra
module Demo::Math;
```

все верхнеуровневые объявления файла помещаются в модульную область `Demo::Math`.

Текущая реализация поддерживает модульную область в пределах одного файла.
Полноценный import/export и раздельная компиляция нескольких файлов не заявляются как реализованные.

### 3.3. Namespace

`namespace` создаёт именованную область видимости:

```astra
namespace Geometry {
    struct Point {
        x: int32;
        y: int32;
    }
}
```

Доступ к объявлениям выполняется через `::`:

```astra
Geometry::Point { x: 1, y: 2 }
```

### 3.4. Порядок верхнеуровневых объявлений

Перед анализом тел функций семантический анализатор регистрирует имена структур, alias-типов и сигнатуры функций во всех верхнеуровневых `namespace` текущего файла. Поэтому функция может вызывать другую функцию, объявленную ниже по тексту, если её сигнатура уже может быть типизирована. Поля структур завершаются до анализа тел функций, поэтому структуры из `namespace` корректно используются в функциях и при доступе к полям.

### 3.5. Shadowing и повторные объявления

Повторное объявление имени в одной области запрещено, кроме перегрузки функций.

Разрешено перекрытие имён во вложенной области:

```astra
let x = 1;
{
    let x = 2;
    print(x);
}
```

## 4. Переменные

### 4.1. Let

`let` создаёт неизменяемую переменную:

```astra
let x = 10;
```

Повторное присваивание в `let` запрещено:

```astra
let x = 10;
x = 20; // ошибка
```

Если тип не указан, он выводится по инициализатору.

### 4.2. Var

`var` создаёт изменяемую переменную и требует явный тип:

```astra
var x: int32 = 10;
x = 20;
```

Инициализатор обязателен.

### 4.3. Lvalue

Присваиваемыми lvalue являются:

- имя `var`-переменной;
- поле изменяемой структуры;
- элемент изменяемого массива.

Если базовый объект неизменяемый, его поле/элемент также не является изменяемым lvalue.

---

## 5. Функции

### 5.1. Объявление функции

Функция имеет:

- имя;
- список параметров;
- необязательный явный тип результата;
- тело.

```astra
fn add(a: int32, b: int32) -> int32 {
    return a + b;
}
```

### 5.2. Вывод результата функции

Если `-> Type` отсутствует, семантический анализатор выводит тип результата по `return expr`.

```astra
fn add(a: int32, b: int32) {
    return a + b; // int32
}
```

Если в функции нет `return expr`, результат считается `unit`.

Если несколько `return expr` встречаются в одной функции с выводом результата, их типы должны быть совместимы.

### 5.3. Return

В функции с явным типом результата:

- `return expr;` требует совместимости `expr` с типом результата;
- `return;` допустим только для `unit`.

В текущей реализации выполняется проверка самих `return`-инструкций.
Полный CFG-анализ всех путей возврата не заявляется как отдельная реализованная возможность.

### 5.4. Main

Программа должна содержать функцию `main` без параметров.
Текущая реализация принимает:

```astra
fn main() -> int32 { ... }
```

и также допускает `int64` как тип результата `main`.

---

## 6. Параметры по умолчанию и именованные аргументы

### 6.1. Параметры по умолчанию

Параметр может иметь значение по умолчанию:

```astra
fn greet(times: int32 = 1) -> int32 {
    return times;
}
```

После параметра со значением по умолчанию нельзя объявлять обязательный параметр без значения по умолчанию.

```astra
fn bad(a: int32 = 1, b: int32) -> int32 { // ошибка
    return a + b;
}
```

Значение по умолчанию типизируется в контексте типа параметра.

### 6.2. Именованные аргументы

Аргумент вызова может указываться по имени параметра:

```astra
fn add(a: int32, b: int32 = 10) -> int32 {
    return a + b;
}

let x = add(a = 5, b = 7);
let y = add(5);
let z = add(5, b = 20);
```

Семантика вызова:

1. позиционные аргументы заполняют ближайшие незаполненные параметры слева направо;
2. именованные аргументы заполняют параметр по имени;
3. один параметр нельзя заполнить дважды;
4. если обязательный параметр не заполнен и не имеет default-значения — ошибка;
5. перед codegen вызов нормализуется к обычному позиционному списку аргументов.

---

## 7. Перегрузка функций

### 7.1. Объявление перегрузок

В одной области видимости можно объявить несколько функций с одним именем,
если их сигнатуры параметров различаются:

```astra
fn show(x: int32) -> int32 { return 1; }
fn show(x: string) -> int32 { return 2; }
```

Повтор той же сигнатуры является ошибкой.

### 7.2. Разрешение перегрузки

При вызове функции семантический анализатор:

1. строит список кандидатов с нужным именем;
2. учитывает позиционные и именованные аргументы;
3. подставляет default-аргументы;
4. считает score совместимости типов;
5. выбирает кандидата с минимальным score.

Score:

- `0` — точное совпадение типа;
- `1` — разрешённое ограниченное неявное преобразование;
- кандидат отбрасывается, если аргумент несовместим.

Если два кандидата имеют одинаковый лучший score, вызов неоднозначен.

### 7.3. Неявные преобразования в перегрузке

Текущая реализация разрешает в перегрузке ограниченные преобразования:

- `int32` в другой целочисленный тип;
- `float64` в другой вещественный тип.

Точное совпадение всегда предпочтительнее.

Пример:

```astra
fn f(x: int32) -> int32 { return 1; }
fn f(x: int64) -> int32 { return 2; }

let a = f(10); // выбирается f(int32)
```

## 8. Методы структур

### 8.1. Объявление метода

Метод объявляется как функция с именем `Type.method`.
Первый параметр должен иметь тип структуры-получателя.

```astra
struct Point {
    x: int32;
    y: int32;
}

fn Point.sum(self: Point) -> int32 {
    return self.x + self.y;
}
```

Если первый параметр отсутствует или его тип не совпадает с типом структуры,
семантический анализатор выдаёт ошибку.

### 8.2. Вызов метода

```astra
let p = Point { x: 10, y: 20 };
print(p.sum());
```

Семантически вызов метода преобразуется к вызову функции, где объект становится первым аргументом:

```astra
Point::sum(p)
```

На уровне реализации объект вставляется в список аргументов перед codegen.

### 8.3. Видимость

Текущая реализация поддерживает методы структур, но не заявляет отдельные модификаторы видимости `public/private`.
Все поля структуры доступны по имени там, где доступен тип структуры.

---

## 9. Структуры

### 9.1. Литерал структуры

```astra
Point { x: 10, y: 20 }
```

Семантически корректен, если:

1. имя указывает на структуру;
2. каждое указанное поле существует;
3. значение поля совместимо с объявленным типом поля.

Текущая реализация проверяет указанные поля и их типы.

### 9.2. Доступ к полю

`obj.field` корректно, если `obj` имеет тип структуры и структура содержит поле `field`.
Результат имеет тип поля.

Если `obj` — изменяемый lvalue, то `obj.field` также изменяемый lvalue.

---

## 10. Массивы

### 10.1. Литерал массива

```astra
let xs = [1, 2, 3];
```

Если ожидаемый тип не задан, тип элемента берётся по первому элементу,
а остальные элементы проверяются на совместимость с ним.
Размер массива равен количеству элементов.

Пустой массивный литерал требует контекста, но текущая реализация выдаёт ошибку для пустого литерала без достаточной информации.

### 10.2. Индексирование

```astra
xs[i]
```

Корректно, если:

- `xs` имеет тип массива `[T; N]`;
- `i` имеет целочисленный тип.

Результат имеет тип `T`.

### 10.3. Runtime-проверка границ

Codegen вставляет проверку:

```text
0 <= i < N
```

При нарушении вызывается runtime-функция ошибки выхода за границы.

## 11. Выражения

### 11.1. Арифметика

Арифметические операции требуют числовых операндов.
Операнды должны иметь одинаковый тип, если контекст заранее не типизировал литерал нужным типом.

### 11.2. Строки

Для строк поддерживаются:

- `+` — конкатенация;
- `==`, `!=` — сравнение;
- `len(s)` — длина в байтах;
- `print(s)`.

### 11.3. Логика

`&&` и `||` требуют `bool` и возвращают `bool`.
Codegen реализует их через короткое замыкание.

### 11.4. Битовые операции

`~`, `&`, `|`, `^`, `<<`, `>>` применяются к целочисленным типам.

Для `&`, `|`, `^` типы обоих операндов должны совпадать.
Для `<<`, `>>` левый и правый операнды должны быть целочисленными; результат имеет тип левого операнда.

Количество сдвига в backend маскируется по ширине левого типа.

### 11.5. If-выражение

```astra
let x = if (cond) { a } else { b };
```

Условие должно быть `bool`.
Ветки должны иметь одинаковый или согласуемый тип.
Результат имеет тип выбранной ветки после согласования.

### 11.6. Конвейерный оператор

`x |> f` семантически эквивалентен `f(x)`.

`x |> f(y)` семантически эквивалентен `f(x, y)`.

После парсинга это представлено как обычный `CallExpr`, поэтому семантика вызова функции применяется без отдельного правила.

### 11.7. Метафункции

- `sizeof(T)` возвращает `int32` и вычисляется как размер типа по layout codegen;
- `typeid(expr)` возвращает `string` с именем статического типа выражения;
- `typeof(expr)` возвращает `string` с именем статического типа выражения.

## 12. Встроенные функции

### 12.1. Print

```astra
print(value)
```

Печатает значение и возвращает `unit`.
Поддерживаемые типы:

- целые;
- вещественные;
- `bool`;
- `char`;
- `string`.

### 12.2. Input

```astra
input() -> string
```

Считывает строку из стандартного ввода через runtime.

### 12.3. Len

```astra
len(value) -> int32
```

Поддерживает:

- `string` — длина в байтах;
- `[T; N]` — константный размер `N`.

### 12.4. Exit и panic

```astra
exit(code: int32) -> unit
panic(message: string) -> unit
```

Обе функции завершают программу через runtime.

### 12.5. Assert

```astra
assert(condition: bool) -> unit
```

Если условие ложно, runtime завершает программу с сообщением:

```text
runtime error: assertion failed at line <N>
```

---

## 13. Runtime-ошибки

Текущий backend генерирует проверки:

1. деление на ноль для `/` и `%`;
2. выход за границы массива для `arr[i]`;
3. провал `assert(false)`.

Сообщения runtime:

```text
runtime error: division by zero at line <N>
runtime error: array index out of bounds at line <N>
runtime error: assertion failed at line <N>
```

`panic(message)` печатает:

```text
runtime error: <message>
```

---

## 14. Диагностики компиляции

Семантический анализатор диагностирует, в частности:

- неизвестное имя;
- неизвестный тип;
- повторное объявление в одной области;
- повтор перегрузки с той же сигнатурой;
- неправильную сигнатуру `main`;
- несовместимые типы;
- присваивание в `let`;
- `break`/`continue` вне цикла;
- вызов не-функции;
- отсутствие подходящей перегрузки;
- неоднозначную перегрузку;
- неправильный default-параметр;
- неправильный именованный аргумент;
- доступ к несуществующему полю;
- индексирование не-массива;
- недопустимое приведение `as`;
- неподходящий тип для `print`, `len`, `assert`.

---

## 15. Честные ограничения текущей семантики

1. Нет полноценного импорта/экспорта между файлами.
2. Нет private/public-модификаторов членов структур.
3. Нет пользовательской перегрузки операторов.
4. Нет generics.
5. Нет nullable-типов.
6. Нет полного CFG/data-flow анализа как отдельной фазы.
7. Нет IR-фазы между семантикой и codegen.
